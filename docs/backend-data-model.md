# Backend data model

This document covers the family, device, pairing and monitoring entities
implemented so far. Moderation events and alert delivery are still to come.

## Relationships

```text
User (accounts) 1 ─── 1 Family
Family         1 ─── n Device
Family         1 ─── n PairingCode
Device         1 ─── 1 MonitoringRule
Device         1 ─── n PairingCode   (redeemed_by, nullable)
```

## Entities

### Family (`accounts.Family`)

The ownership boundary for everything a parent account controls.

| Field | Type | Notes |
|---|---|---|
| `owner` | OneToOne → User | One family per parent account |
| `name` | CharField(100) | Optional display name |
| `created_at`, `updated_at` | DateTime | Automatic |

`Family.for_user(user)` returns the parent's family, creating it on first use.

### Device (`devices.Device`)

A child device that belongs to a family.

| Field | Type | Notes |
|---|---|---|
| `family` | ForeignKey → Family | Required |
| `name` | CharField(100) | Human-readable device name |
| `platform` | CharField | `android` only for now |
| `installation_id` | UUID | Unique, generated on creation |
| `credential_hash` | CharField(128) | Hash of the device credential, never plaintext |
| `paired_at`, `last_seen_at` | DateTime | Nullable lifecycle timestamps |
| `monitoring_enabled` | Boolean | Whether the device is actively monitoring |
| `is_revoked` | Boolean | Revoked devices cannot sync |
| `created_at`, `updated_at` | DateTime | Automatic |

Query helpers: `Device.objects.active()`, `.monitoring()` and
`.for_family(family)`. Lifecycle helpers: `mark_paired()`, `mark_seen()` and
`revoke()`, which also clears the stored credential.

### PairingCode (`pairing.PairingCode`)

A short-lived, single-use code that links a child device to a family.

| Field | Type | Notes |
|---|---|---|
| `family` | ForeignKey → Family | Owning family |
| `code_hash` | CharField(64) | Unique SHA-256 digest; the plaintext code is never stored |
| `expires_at` | DateTime | Ten minutes after issue by default |
| `used_at` | DateTime | Set when redeemed |
| `revoked_at` | DateTime | Set when revoked |
| `redeemed_by` | ForeignKey → Device | Nullable redemption metadata |
| `created_at` | DateTime | Automatic |

Codes are generated by `pairing.codes.generate_code()` in the form
`GL-XXXX-XXXX`. `PairingCode.issue(family)` returns the record plus the
plaintext code once, and `record.redeem(device)` enforces single use.

### MonitoringRule (`monitoring.MonitoringRule`)

Parent-managed configuration for one device.

| Field | Type | Notes |
|---|---|---|
| `device` | OneToOne → Device | One rule per device |
| `sensitivity` | CharField | `low`, `standard` or `strict` |
| `sample_interval_seconds` | PositiveSmallIntegerField | Between 5 and 10 seconds |
| `monitored_packages` | JSONField (list) | Android package names, deduplicated on clean |
| `version` | PositiveIntegerField | Incremented on every configuration change |
| `acknowledged_version` | PositiveIntegerField | Last version applied by the child |
| `created_at`, `updated_at` | DateTime | Automatic |

`bump_version()` records a change, `acknowledge()` stores the child's applied
version, and `needs_acknowledgement` exposes whether a sync is still pending.
